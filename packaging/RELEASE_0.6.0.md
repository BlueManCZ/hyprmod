# HyprMod 0.6.0 release checklist

This release needs two library releases before the app can advertise every
Hyprland 0.57 feature through a normal package install.

## 1. Publish the upstream libraries

Order matters: the config package depends on the schema package.

1. `hyprland-schema` 0.7.3
   - Merge the branch that adds the `v0.57.0` schema and migration.
   - Tag `v0.7.3`, publish to PyPI.
2. `hyprland-config` 0.9.20
   - Merge the branch that adds the 0.57 rule effects and Lua query stubs.
   - Tag `v0.9.20`, publish to PyPI.

Both release trees already contain `dist/` artifacts locally for inspection.

## 2. Bump the app floors

After both packages are on PyPI:

- `pyproject.toml`: `hyprland-config>=0.9.20`, `hyprland-schema>=0.7.3`.
- Run `uv lock`.
- `nix/hyprmod.nix`: bump both pins and their hashes.
- Run `uv run pytest tests/test_nix_pins.py -q`.
- Remove the `V3_BOOL_EFFECTS` feature gate in
  `hyprmod/core/window_rules/_model.py` once the floor guarantees support.

## 3. Publish HyprMod 0.6.0

- Tag `v0.6.0` from the release commit.
- Update the AUR package using `packaging/aur/README.md`.
- Build and smoke-test the wheel:

```bash
uv build
uv run pytest tests/ -q
```

## 4. Upgrade verification

On a Hyprland 0.57 machine:

1. Open HyprMod. It must not reload the compositor.
2. Check `hyprctl configerrors` stays empty.
3. Confirm the Decoration page shows `Blur variant`, `Wobble`, and `Glow`.
4. If an old `hyprland.conf` exists next to an autogenerated
   `hyprland.lua`, confirm the recovery banner appears and that migration
   writes a backup before replacing the placeholder.
5. Confirm opening and closing the app leaves the active workspace and
   window layout untouched.
